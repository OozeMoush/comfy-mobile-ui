## 2026-10-06 — identify Codex self-reexecution failure

The user reproduced the sandbox executable-start failure in a normal WSL terminal. Further fixed-sentinel diagnostics identified the executable bubblewrap cannot start as **Codex itself**, rather than the requested Node or shell. The same failure occurs in the actual PR workspace, so it is not confined to the nested fixture. No outside filesystem was searched or probed, and no raw host executable paths were recorded.

The [0.160.0 upstream implementation](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/linux-sandbox/src/linux_run_main.rs) re-executes `current_exe()` inside the restricted mount view. [Upstream issue #29049](https://github.com/openai/codex/issues/29049) reports restricted profiles hiding that executable. Together with the local diagnostic, this identifies the bootstrap failure mechanism; it does not establish that copying runtimes will resolve every subsequent issue.

Prepared a remedy without outside filesystem grants: support native regular executable files at `.codex/runtime/codex` and `.codex/runtime/node`, use the local Codex for both app-server and interactive startup, and copy both files into the nested fixture's protected `.codex/runtime/`. Reject symlink/partial/non-executable installations; gitignore the binary files. There is no automatic host-file discovery, copying, download or installation.
